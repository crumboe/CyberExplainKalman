Introduction: The Hidden State

Error is inescapable

What is 5 cm truely? Can we ever measure a perfect 5cm?

Yes and No

  • To a drill press : 5cm => 5cm +- .5cm
  • To a mill : 5cm => 5cm +- .005cm
  • To an ASML Photolithography Machine: 5cm => 5cm +- 0.000002cm

Today’s Goal

The Mathmatics of finding truth through Error, and incorporating new data as Evidence rather than truth. Since by definition we cannot measure the error of any particular measurment, We use probability to model the likelyhood of sensing a true value

Boolean vs. Probabilistic Logic

Boolean Logic

# Boolean logic example
# if (Shooter_will_make_the_shot == True):
#     shoot

Probabilistic Logic

# Probability logic example
# if (Probability_we_make_the_shot >= 80%)
#     shoot

Key difference:

Combining evidence with trust levels enables better decisions.

  • Boolean: Instantaneous sensor read → immediate judgment

  • Probabilistic: Averages sensor noise, reduces false positives/negatives

Caveat:

There are alternative filtering approaches that don’t rely on probability:

  • Rolling average on distance sensors
  • Debounce period on limit switches
  • Moving median filters
  • Exponential smoothing
  • These can work very well depending on implementation and use case

Understanding Set Space

  • We want a number that represents how often something happens, or does not
  • If you know nothing about an event, you could assume it’s a 50:50 chance, pass or fail, it will happen or it wont
  • With Evidence about the type of event (I.E. Rolling a 2 on a D6 Die) you can refine your guess, in this case to 1:6
  • You can also experiment to find probability. If given a weighted die, you could roll it many times to gather data, and hone in on the true likelyhood of any given face landing up.

Bayes Theorem

\[P(\text{Target Hit} \mid \text{Shooter Broken}) = \frac{P(\text{Target Hit} \cap \text{Shooter Broken})}{P(\text{Shooter Broken})}\]

\[P(\text{Target Hit} \cap \text{Shooter Broken}) = P(\text{Shooter Broken}) \times P(\text{Target Hit} \mid \text{Shooter Broken})\]

Understanding Set Space

Bayes Theorem – Generally

\[P(\text{Event} \mid \text{Evidence}) = \frac{P(\text{Event} \cap \text{Evidence})}{P(\text{Evidence})}\]

\[P(\text{Evidence}) = \frac{P(\text{Event} \cap \text{Evidence})}{P(\text{Event} \mid \text{Evidence})}\]

\[P(\text{Event} \cap \text{Evidence}) = P(\text{Evidence}) \times P(\text{Event} \mid \text{Evidence})\]

Understanding Set Space

Bayes Theorem – Generally

For events that are dependent, finding The intersection (AND) can be difficult. So Bayes tells us =>

\[P(\text{Evidence} \cap \text{Event}) = P(\text{Event}) \times P(\text{Evidence} \mid \text{Event})\]

So we substitute and rewrite the our original equation as:

\[P(\text{Event} \mid \text{Evidence}) = \frac{P(\text{Event}) \times P(\text{Evidence} \mid \text{Event})}{P(\text{Evidence})}\]

Understanding Set Space

Bayes Theorem — Evidence Accumulates

For dependent events, Bayes gives us a practical way to update a belief with new evidence:

\[ P(\text{Event} \mid \text{Evidence}) = \frac{P(\text{Event})\,P(\text{Evidence} \mid \text{Event})}{P(\text{Evidence})} \]

1. Start with a prior Our confidence before the new observation.

2. Evaluate the evidence Ask how likely this observation is under the event.

3. Calculate the posterior The updated confidence after incorporating the evidence.

4. Repeat Use the posterior as the prior for the next observation.

Reliable evidence strengthens confidence; contradictory evidence weakens it. Repeating the loop produces increasingly informed beliefs.

Activity — Diagnose the Hidden Motor

The question

One box was chosen and stays hidden. Each bead is a new test result. Which motor is more likely?

Hypothesis A — motor is good

90% green · 10% red

A red result is unusual when the motor is healthy.

Hypothesis B — motor is broken

50% green · 50% red

A red result is five times more likely when it is broken.

Starting prior: no preference yet Good 50% Broken 50%

Ask the room: If the first test is red, which hypothesis should gain confidence—and why?

Test 1 — A Red Result

Step 1: weight each hypothesis by how well it predicts red

Good motor Prior × likelihood
\(0.50 \times 0.10 = 0.05\)

Broken motor Prior × likelihood
\(0.50 \times 0.50 = 0.25\)

Step 2: normalize the two weights

\[ P(\text{Broken}\mid\text{Red}) =\frac{0.25}{0.05+0.25} =\mathbf{83.3\%} \]

Good 16.7%Broken 83.3%

The posterior is 83.3% broken. That posterior becomes the prior for the next test.

Test Again — A Green Result

Step 3: reuse the posterior as the new prior

Previous posterior83.3% broken→New prior83.3% broken

Step 4: apply the green likelihoods

Good motor \(0.167 \times 0.90 = 0.150\)

Broken motor \(0.833 \times 0.50 = 0.417\)

\[ P(\text{Broken}\mid\text{Red, Green}) =\frac{0.417}{0.150+0.417} =\mathbf{73.5\%} \]

Good 26.5%Broken 73.5%

Green is evidence for a good motor, so confidence in “broken” falls—but one green result does not erase the earlier red result.

A Kalman Filter Is Bayes in Motion

Bayes asks one useful question

“Given my old guess and this new evidence, what is my better guess now?”

Old guess + new evidence → updated guess

A Kalman filter asks it again and again

  • Old guess: where motion says the object should be.
  • New evidence: where a sensor says the object is.
  • Updated guess: the most believable location right now.
  • Then motion carries that answer forward to the next moment.

The Four-Step Loop

1

Make a guess

Use the last position and direction of travel to predict what happens next.

→
2

Read the sensor

Get a fresh—but imperfect—observation of where the object is.

→
3

Compare confidence

Ask which source has usually been more dependable.

→
4

Update the guess

Move toward the sensor by the appropriate amount, then repeat.

Predict where it is going. Check what the sensor saw. Blend them according to trust.

Motion Fills the Gaps

Sensors give us snapshots. The object keeps moving between those snapshots.

0 seconds Sensor sees 2.0 m Start with an observed position

1 second No new reading Motion predicts about 3.0 m

2 seconds Sensor sees 4.2 m Use it to correct the prediction

Remember only position

“It was at 2.0 m.” The estimate becomes stale as soon as the object moves.

Remember position and motion

“It was at 2.0 m and moving right.” Now we can make a useful prediction while the sensor is silent.

Motion carries the estimate forward. The next sensor reading pulls it back toward reality.

The “Trust Dial” Controls the Move

Dial near 0

Mostly trust motion

The sensor is unreliable, so the guess barely moves toward it.

Dial in the middle

Blend both

Both sources have value, so the answer lands between them.

Dial near 1

Mostly trust the sensor

The reading is dependable, so the guess moves close to it.

Updated guess = motion prediction + some fraction of the gap toward the sensor

Engineers call that fraction the Kalman gain. It is calculated from the relative uncertainty of the prediction and the sensor—not chosen by hand each time.

Why the Combination Works Better

Motion only

It drifts

Tiny errors accumulate, so the predicted position slowly wanders away.

Sensor only

It jitters

Individual readings bounce around, even when the object moves smoothly.

Kalman filter

It stays smooth and grounded

Motion fills the gaps; sensors keep the prediction connected to reality.

A Kalman filter does not claim to know the exact truth. It keeps a best guess plus an honest measure of confidence, then improves both whenever new evidence arrives.

The Big Picture

Prediction where motion says it should be

+

Observation where the sensor says it is

Then repeat at the next time step.

A Kalman filter is a repeating trust exercise: predict, observe, blend, and carry the improved guess forward.
